# LEA catalog cost benchmark

This benchmark answers one narrow, reproducible question:

> Given the same workflow stages and typical token counts, how much does LEA's
> role-aware model route cost compared with assigning every stage to one model?

It does **not** call model APIs and does **not** measure correctness, latency, coding
quality, or benchmark contamination.

## Reproduce

```bash
lea benchmark
lea benchmark --json
lea benchmark --baseline grok-4.6
```

The command requires no API keys. It ignores local model pins and assumes every native
provider in the catalog is reachable, making results deterministic across machines.

## Method

1. Classify each fixed task with LEA's deterministic local classifier.
2. Build a route from the default model policy with user pins disabled.
3. Use the role-level typical input/output counts in `agentflow/catalog.py`.
4. Price each LEA stage with its routed model.
5. Price the exact same stages and token counts with the selected baseline model.
6. Report `(1 - LEA / baseline) × 100`.

The fix stage is included when the route reserves it for a possible review loop. It is
included on both sides of the comparison.

## Limitations

- Catalog prices can change. The JSON result includes `catalog_as_of` and official
  `pricing_sources`; the full provenance is in [the catalog notes](../docs/model-catalog.md).
- Real prompts and completions vary in length.
- Provider caching and discounts may change actual invoices.
- Lower estimated price does not prove equal or better output quality.
- The all-provider assumption shows the intended route, not what every user can reach.

Future live benchmarks should publish task fixtures, repository commits, judge prompts,
raw usage, model revisions, repeated trials, and confidence intervals. Until then, this
benchmark should be cited only as a deterministic routing-cost estimate.
